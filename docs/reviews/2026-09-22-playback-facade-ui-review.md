# Playback, facade and Swift UI review (2026-09-22)

Reviewer: Opus 5.5 read-only pass over Engine/Audio, Engine/Playback, Engine/Facade, App and their tests at commit 223ab80 (git archive extraction, private DerivedData). Findings 1, 2, 3, 5, 6 were reproduced with probe tests. At 223ab80 the PlaybackController is not yet wired into VEEngine/the app (phase 5b), so the controller findings are latent; facade and app findings are live.

## Ranked findings

1. HIGH (verified): an import finishing during a timeline drag breaks the drag. `finishImport` calls `closeCoalescingIfOpen` (VEEngine.mm:800; defined 1026-1032), clearing `_coalescingKey`/`_coalescingBase` mid-gesture; `removeAsset` (VEEngine.mm:880) does the same. TimelineView.swift:268-281 keeps sending the total offset from the gesture origin, so `moveClips` (VEEngine.mm:1146) adds it to the current position on every event. Probe: drag 1.0 s, import completes, drag to 1.5 then 2.0 → clip at 4.5 s; drag split into three undo steps around the Import; Escape does nothing. Also `importMediaAtURLs` never captures `_projectGeneration`, so an import started before New/Open lands in the next project. Fix: never close a user coalescing group from async completions (push the import uncoalesced without touching the keys, or queue it until endCoalescing); capture the generation and drop stale results.

2. HIGH (verified): undoing an import reuses the asset id; id-keyed caches serve the old media. `ImportAssets::revert` restores `project.ids = idsBefore_` (VEFacadeCommands.mm:43), contradicting VETypes.h:7-8 ("never reused"). Probe: import wav (id 6) → undo → import mp4 → id 6 again, `waveformForAsset:6` returns the WAV peaks. Caches keyed by id and never purged: FrameCache (DecodePool::registerAsset reopens streams but keeps frames, DecodePool.mm:187-210), ThumbnailService memory cache (ThumbnailService.h:107/149), Swift caches (MediaCaches.swift:13-18, 108). Worst: `_bookmarks[id]` (VEEngine.mm:810-812) keeps the old bookmark when creating the new one fails → save writes A's bookmark for B → reopen relinks B to the wrong file. Fix: monotonic id generator across undo (restore the asset list, never roll back `ids`), or purge every id-keyed cache and bookmark on remove/re-add. Clip ids are rolled back the same way; header promise is false.

3. HIGH (verified, data loss): multi-clip move with a track offset overwrites the selection's own clips. `moveClips` orders by timelineStart only (VEEngine.mm:1180-1186) and applies each MoveClip with overwrite semantics. Probe: X on V1 [0,2), Y on V2 [1,3), move both up → X cuts Y; Y ends on V3 as [1,2) sourceIn 5 s; success reported. Fix: lift all selected clips first then place them (one command), or order by destination track and refuse when a destination overlaps another selected clip's source slot. Regression test.

4. HIGH (by design, measured): play, seek-while-playing, setRate, JKL and setMuted block the caller up to ~300 ms and restart the audio device. `startPlaybackLocked` (PlaybackController.mm:569-605) holds `mutex_` across `mixer_->prime(prerollTimeout)`, sleep-polls for frames, and `output_->start()` (synchronous `[AVAudioEngine startAndReturnError:]`); `stopPipelineLocked` (545-549) calls `[engine stop]` on every pause/seek/rate change. Measured preroll 107.7 ms on tiny local media; 300 ms cap + engine start on cold 4K/network. Main thread freezes (budget < 16 ms); tick thread and readers blocked; each L press rebuilds the audio route (Bluetooth: hundreds of ms and pops). Fix: async play (state Prerolling, return, tick thread finishes preroll and publishes Playing); keep AVAudioEngine running while a sequence is open (mixer renders silence) and stop after an idle timeout; rate change within the same direction without full preroll.

5. MEDIUM-HIGH (verified): display-path clock not monotonic and ignores the device timestamp. Frame source uses `clock.timeAt(targetTimestamp)` when the host clock is not virtual (PlaybackController.mm:167-172); `timeAt` has no monotonic guard (Clock.mm:178-181); interpolation extrapolates up to lastBlock + 50 ms (124-139). Probe: after a callback 25 ms late, timeAt drops 0.0250 → 0.0107 s (14.3 ms backwards) → N+1, N, N+1 at a frame boundary. Causes: callback host time is mach_absolute_time() at block entry (AudioOutput.mm:34), render block ignores its AudioTimeStamp (166-169); latency compensation subtracts only outputNode.presentationLatency (135), ignoring the IO buffer and mixer resampling delay (video leads audio ~10-25 ms, never measured). Tests never take this path (PlaybackTestSupport.mm:125-126 passes targetTimestamp 0, null output). Fix: use timestamp->mHostTime (flag-checked); per-epoch monotonic guard in the frame source; include IO buffer duration and converter latency; add a loopback/real-output measurement.

6. MEDIUM (verified): seeking back and replaying clips the head of any already-played audio clip. `setGraph` reuses a source with unchanged mapping without repositioning (AudioMixer.mm:163-175); `prime` repositions only sources within 0.25 s of the playhead (221-245); when reached, `read()` finds pos < consumerExpected on a consumed segment and self-repositions (ClipAudioSource.mm:150-158), outputting silence meanwhile. Probe: play C [1,3) from 1 to 2 s, then play from 0.2 s → 512 silent samples (10.7 ms) + 1 underrun at C's head; fresh source 0/0. Fix: on setGraph while stopped, seekTo(max(spanStart, playhead)) every reused source not already positioned there.

7. MEDIUM: device-change handling racy; can silently freeze playback. Notification block runs on AVAudioEngine's posting thread (queue:nil, AudioOutput.mm:186-191) → startLocked → latencyClock->setOutputLatency (139-141) writes Clock::control_/anchor_ (Clock.mm:54-57) unsynchronised against controller clock.start/stop/setTime, violating Clock.h:27-29 and the SeqLock single-writer rule; a seek during a device switch can publish a torn/stale anchor with an old epoch → mixer samples ignored → video freezes. TSan doesn't flag it (atomics hide the plain-struct race). Failed restart returns quietly (251-256): clock stays AudioSamples with no callbacks, state Playing, picture frozen, no error. Teardown: ~Impl removes the observer (78-82) but a running handler still dereferences self (UAF). Fix: serial queue owned by the controller (or post to the controller, apply latency under its mutex); surface restart failure → host clock or pause with error; guard teardown.

8. MEDIUM: snapping during a move uses the live previewed model (TimelineView.swift:267-271 candidates from store.timelineModel, which already has the previous step's overwrite; crossed clips are split at the dragged clip's previous edges, not excluded) → clip advances in ~8 pt jumps with a flickering snap line. Fix: candidates from the pre-gesture snapshot captured at startDrag (engine keeps `_coalescingBase`).

9. MEDIUM: closing with unsaved changes asks twice; Finder-open at launch is dropped. windowShouldClose → confirmDiscardingChanges (WindowAccessor.swift:77-80, ContentView.swift:46-47); after "Don't Save" the last window closes → app terminates (AppDelegate.swift:7-9) → applicationShouldTerminate prompts again (11-15); Cancel leaves the app running with no window. application(_:open:) requires `documents`, set only in the window's onAppear (VidEditApp.swift:22-25) → cold-launch open event dropped. Fix: confirmed/discarded flag or mark clean after Don't Save; set appDelegate.documents in App.init or buffer pending URLs.

10. MEDIUM (perf): one ObservableObject drives the whole window. ProjectStore publishes ~25 properties (ProjectStore.swift:42-78); timeline, bin, inspector, source monitor, transport and AppCommands (VidEditApp.swift:39-41) all observe it. Every change rebuilds store.timelineModel (ProjectStore.swift:164-186, also per drag event), assetsByID (TimelineView.swift:162), full Canvas redraw with waveforms recomputed every 2 px; layout(forTrack:) recomputes and sorts per clip rect. Source-monitor scrub and scroll already do this at 60 Hz; playhead at 30-60 Hz will redraw the whole window per frame. Fix: split playhead/scroll/zoom into separate observables; cache timelineModel per changeCount; pre-render waveform strips; playhead in an overlay layer.

11. MEDIUM: source monitor is a stand-in and fills the disk cache: thumbnails up to 1920 px (SourceMonitorView.swift:57-70), ThumbnailService writes a PNG per request (ThumbnailService.mm:434-446), 1-3 MB each per scrubbed frame; resizing changes keys. In/out points stored at timescale 600 off the frame grid (87) and shown with the sequence's timecode rate (116). Fix: VEPreviewView-based source monitor via DecodePool scrub (planned); until then bypass disk cache for large/scrub requests; snap in/out to the asset frame grid.

12. LOW-MEDIUM: Cmd+Z during a drag cancels the drag AND undoes the previous edit (ProjectStore.swift:202-205). Fix: stop after cancelling when a gesture was active.

13. LOW-MEDIUM: producer threads never idle: each ClipAudioSource wakes every 5 ms forever once full (ClipAudioSource.mm:365-371, 197-201); after pause the stopped plan keeps every source (hundreds of wakeups/s idle); retired plans freed only on next publish() (AudioMixer.mm:85-91); sources leaving a plan are destroyed (joining a producer possibly inside a decoder seek) under mixer and controller mutexes from the tick thread (PlaybackController.mm:957-997), stalling main-thread callers. Fix: block without timeout when paused/full, wake on reposition/consumer progress; drain retired plans from the tick thread; destroy sources outside locks.

14. LOW: AutomaticAudioOutput falls back to null forever after one failed start (AudioOutput.mm:392-419); pause cuts audio with no fade (AudioMixer.mm:392-396); gain edits swap envelopes in a step (zipper); 2x box decimator aliases; SeqLock readers spin without pause (Realtime.h:133-147). HUD: fps never reset after pause; a cached frame that fails texture mapping counts as hit/exact while drawing black (PlaybackController.mm:200-214). Facade: VE_ASSERT_MAIN is NSAssert (compiled out in Release, VEEngine.mm:55), missing on hardwareCaps/backendNames/frameCacheBudgetBytes getter; VEAssetInfo.useCount stale (no assets notification on edits); memory pressure purges only FrameCache. Swift: caches' `failed` sets permanent (MediaCaches.swift:73, 134); ruler scrub snapping blocked by the playhead's own candidate (TimelineView.swift:137); video-row trackOffset applied to selected unlinked audio clips (274-276); `drag` state leaks if cancelled without onEnded; key monitor takes arrows/space from focused non-text controls (KeyboardController.swift:75-84).

## Done properly (do not redo)
SeqLock and SPSC memory orders correct, indices only grow (no ABA), reposition request is one packed CAS. Plan handoff: render thread frees nothing; unadopted plans deleted by control side, adopted via retire queue; no shared_ptr refcounts on the render thread. Render path proven allocation-free by a hooked test with a positive control. Mixer envelopes per-sample exact (2e-6), constant-power law verified (1e-5). Audio source reuse keyed by mapping (edit elsewhere keeps the playing clip seamless, tested); resampler phase closed-form. Clock epoch tagging drops late samples across seeks; now() has a monotonic guard; tick math exact. Frame source swaps pins only after new pins are taken; observer callbacks coalesced to one pending block with weak captures. Facade snapshots truly immutable; no retain cycles among VEEngine, ProgramFrameProvider, preview view. Save atomic and byte-identical on re-save; security-scoped access balanced. Coalesced relative multi-move works for horizontal moves. Swift: no force unwraps/try!/fatalError; key monitor idempotent and skips text fields; scroll monitor removed on dismantle; CloseGuard forwards the SwiftUI window delegate. TSan: 63 Audio/Playback/VEEngine tests clean (a deliberate race probe confirmed TSan reports reach the log).

## Test gaps
1. Real display path never tested (no targetTimestamp, no AVAudioEngine): play through AudioOutput with jittered callbacks and assert presented indices never go backwards.
2. Drift test proves arithmetic, not sync: virtual clock advances exactly one block per block; waits for decoded frames/audio before each step (late/dropped/underrun zero by construction); worstClockLag compares against the same clock.now() read (vacuous); Apple MP4 only, no MKV/FFmpeg playback test.
3. Beep checks allow 1 ms (48 samples); the 0.083 ms bias is the detector's 4-sample threshold latency (BurnIn.mm:211-216). Assert expected + 4 samples within ±1.
4. AVAudioEngine device test allows 60 ms per 600 ms (cannot catch a 44.1/48 kHz counting error); no test runs the configuration-change handler concurrently with transport.
5. Missing: seek back then replay into a played clip; edit to the playing clip's own mapping/gain/track during playback; cold-cache play asserting caller block time; end of sequence at 2x; multi-clip move with track offset; undo import then import; import completing mid-coalescing; open after moving a media file; save/open/missing-asset under a real sandbox.
6. AppTests: smoke test triggers the thumbnail/waveform fetches it then asserts (MainWindowSmokeTests.swift:51-52, 60-62) and never checks timeline drawing; no tests for TimelineView gesture states, DocumentController close/quit/save-failure, WindowAccessor close guard.
7. Wall-clock assertions that will flake under load/TSan: fps > 20, statuses <= 40, playingSeen > 10, 2x advanced/wall ±0.1, samples > 150, prerollMs < 400.
